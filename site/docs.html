FileMapper is a local filesystem and semantic evidence workspace. This static website includes documentation, a synthetic illustration and a separate reviewed public-source game report. It is not the local service.

Install a prepared Windows package

Obtain the package and SHA-256 file from the project's actual GitHub release once one has been published. Check the manifest's source revision, runtime identifier, and signing status. This page does not claim a release has already been published.

Get-FileHash .\FileMapper-<version>-win-x64.zip -Algorithm SHA256
# Compare with the separately obtained SHA-256 value, then extract the ZIP.
.\operations\Install-Local.ps1 -StageOnly
.\operations\Install-Local.ps1

The per-user installer stages and probes the package, backs up the database, then activates the service. It prints the local URL and restart command. PowerShell 7.6 or newer is required for operations and the typed module. A self-contained service/CLI package does not require a separately installed .NET SDK.

Keep the local service token private. Enter it only into your own loopback FileMapper interface. This public website has no token entry or local API integration.

Build from source

Install the SDK pinned in global.json. The service and CLI use .NET 11 and C# 15; the PowerShell module targets its supported .NET 10 host.

dotnet restore FileMapper.sln --locked-mode
dotnet build FileMapper.sln -c Release --no-restore
dotnet run --project src/FileMapper.Cli -c Release -- --help
./eng/Build-Release.ps1 -RuntimeIdentifier win-x64 -OutputDirectory artifacts/release

Repository automation uses PowerShell and compiled C# utilities. No Python runtime is required. Never run or import untrusted target code merely to inspect it.

What an observation means

  • Logical size, allocation, content equality, and reclaimable storage answer different questions. Unknown allocation is not zero.
  • Snapshot completeness, scan errors, exclusions, and parser budgets remain part of each result.
  • Source analysis is bounded. Candidate flows and unresolved calls do not prove runtime exploitability or safety.
  • Git authorship and CODEOWNERS are advisory attribution. Explicit manifests and matching hashes can support artifact relationships; they do not prove a build executed.
  • Spatial positions identify categories and snapshot layers. They do not measure similarity or provide machine learning. Historical layers show recorded states, not inferred trajectories.

Persistent learning and whole shapes

The local learning arena records vocabulary and source encounters over time. Only explicitly labelled examples update its two supervised relevance heads. Native source identities, measured bytes and code witnesses remain separate evidence. Saved checkpoints and arenas are immutable; later observations cannot change an earlier match.

The XYZ game preserves complete pieces, supports native orientations and line or plane clears, and scores connected supplied patterns with a small capped learned bonus. New models are visibly untrained. A high game score does not establish useful retrieval, semantic truth, or CodeQL/TreeSize parity. The public synthetic atlas does not train a model or connect to your local service.

Open the complete two-family, twelve-arm bakeoff. All episodes were independently replayed. The report retains exact source mappings, bounded learning scope and unequal computation budgets; it makes no general superiority or code-analysis accuracy claim.

Release status and verification

Development packages may be unsigned. Signing is real only when an accessible trusted certificate is supplied; no certificate is invented. A signed installation can require the expected publisher thumbprint with -RequireSignature -SignerThumbprint.

Each payload contains a file SHA-256 manifest and CycloneDX dependency/runtime/file SBOM. Release scripts use locked restore, isolated build outputs, stable archive ordering and fixed archive timestamps. A reproducibility claim requires actual build comparison; timestamped signatures are time-dependent.

Windows is the primary installation target. A cross-published Linux binary is not evidence of Linux runtime acceptance. Consult the exact release's checks and limitations. No blanket production-readiness or benchmark-accuracy claim is made here.

Privacy and safe operation

The public demo contains only deliberately invented data. It sends no analytics, accepts no credentials, and never requests your local service. Private inventory, private source, local findings and tokens stay outside this publication payload. The separate held-out report includes selected public repository paths, source identities and bounded game results; it received static review, with browser interaction unverified.

The local service uses loopback binding and scoped credentials. A scan may expose sensitive paths or source in its own results; inspect exports before sharing them. Diagnostics omit token contents but optional logs may contain paths and error detail. Stop legacy database writers before upgrade when they do not implement the maintenance protocol.
